# 「AI 引导式学习（Guided Learning）」产品设计说明

> 核心引导语：**「当你感到愤怒、委屈、焦虑或兴奋的时候，你是否愿意先问一句：这份情绪想告诉我什么？」**
>
> 目标不是把情绪处理掉，而是让人愿意先**问一句**——把情绪当成信号而不是故障。

> **产品口径已与架构文档 `docs/guided-learning-design.md` §10（Q1–Q10）对齐**。文中标注「与架构文档对齐」的段落为本次修订点，涉及：§5.1 强度评分口径与兜底族、§5.4 阈值复位规则、§6.2 三档渲染口径、§6.3 `{{quote}}` / `{{alt}}` 与 evidence 例外、§7.3 折叠层次、§8.8 同族轻提示、§10.1 撤回 `emotion` 字段。

---

## 1. 目标与非目标

### 一句话目标

在陪伴对话中，当用户说出明显的情绪时，除了正常回应，再给一次**结构化的情绪觉察引导**：先把情绪命名出来，再读它可能指向的需要，最后留下一个可以自己回答的问题和一件很小的事。

### 与 MoodHub 定位的一致性

| MoodHub 的立场 | 本功能如何守住 |
| --- | --- |
| 自我觉察，不是诊断 | 全程只做「命名 + 一种可能的读法」，每次都声明这是基于这一句话的一版解释，可被推翻 |
| 非评判、不说教 | 引导语不出现「你应该」「你要学会」「别想太多」；不评价情绪好坏 |
| 本地优先 | 情绪识别与引导正文**默认由本地模板生成**，不依赖云端；云端模型只是可选增强，且受既有两条硬约束限制 |
| 可解释、可纠正 | 引导卡复用 `MH.xai` 的三档 + 依据 + 请求校正，并挂「符合 / 部分符合 / 不符合」反馈 |
| 安全优先 | 命中危机词时引导**完全不触发**，只出求助资源 |

### 它不是什么（明确的非目标）

- **不是心理治疗**，也不是任何形式的干预、训练课程或疗程；没有「疗程进度」「打卡天数」「改善率」。
- **不是诊断**：不给情绪打分定性，不说「你有焦虑倾向」，不输出任何障碍名称作为结论。
- **不给建议式说教**：小行动是「一件可以试的小事」，不是「你应该做」；用户不点「我试试」就不再提。
- **不替代真人**：不因为有了引导就减少求助资源的露出；孤独 / 危机场景仍然直接指向热线。
- **不做连环追问**：一次触发只出一张卡，不追问「为什么」「还有吗」。
- **不新增外发**：引导功能不产生任何新的网络请求；`MH.store.models.allowExternal()` 为 false 时引导正文一律本地生成。

## 2. 用户故事

**A. 被动被情绪困住的人**

1. 作为一个刚跟同事吵完、气得手抖的人，我想有人先帮我说出「我现在是愤怒」，而不是让我自己分析，这样我才不用一边生气一边还得想清楚。
2. 作为一个觉得「凭什么最后是我背锅」的人，我希望被看见的是**委屈**而不是被当成矫情，这样我才敢继续往下说。
3. 作为一个凌晨三点把明天的错想了七遍的人，我想知道这份焦虑到底在提醒我什么，这样它就不再只是一团让我睡不着的雾。

**B. 主动想复盘的人**

4. 作为一个状态很好、刚做成一件事的人，我想把这份「兴奋」看清楚是哪一部分带来的，这样以后低气压的时候我能照着它找回来。
5. 作为一个习惯记录的人，我希望引导最后能落到一句可以写进记录里的话，这样它不会聊完就散掉。
6. 作为一个经常重复同一种情绪的人，我想看到「上次我们聊到过它」，而不是每次都从零开始被讲一遍同样的道理。

**C. 被自动触发打扰到的人**

7. 作为一个只是随口说了句「有点烦」的人，我不想每次开口都被拉去做情绪练习，这样我才会继续用这个树洞。
8. 作为一个已经被引导过一次、现在只想静静说话的人，我希望有一个明确的「这次先不了」，而且点了之后**七天内不再被主动提起**，而不是今天换个说法再来一遍。

## 4. 情绪识别范围

> 语气原则：**命名不带评价，信号只是一种可能，问题留给本人回答，行动要小到今天就能做。**
> 每族的「信号」一律写成「它常常在说……」「一种可能的读法是……」，不写成结论。

### 4.1 愤怒 `anger`

- **用户可能的说法**：「气死了」「烦死了」「凭什么这么对我」「想骂人」「受不了了」「窝火」
- **情绪命名**：愤怒（也可能夹着委屈）
- **它通常指向的需求或信号**：通常在说有一条边界被越过了，或者一个需要没被接住。它本身不是坏事。
- **共情确认（示范）**：「听起来，这更像是一股愤怒——不是你脾气差，是有什么东西顶到你了。」
- **反思问题**：
  - 如果把它翻译成一句「我需要……」，会是哪一个词？
  - 这件事里，真正被碰到的那条线是什么？
- **一件小事**：先给身体一个出口。把想说的话写下来，先不发。等心率降下来再决定要不要表达。

### 4.2 委屈 `grievance`（本次新增，现有 `INTENTS` 无此族）

- **用户可能的说法**：「我明明已经很努力了」「凭什么最后是我背锅」「没人看见我做的那些」「我说了不算」「算了，我不重要」
- **情绪命名**：委屈
- **它通常指向的需求或信号**：它常常指向「被看见」「被公平对待」这个需要，也常和愤怒叠在一起——愤怒对外，委屈对内。
- **共情确认（示范）**：「这听起来是委屈。被忽略的付出也是付出，它不是矫情。」
- **反思问题**：
  - 在这件事里，你最希望被谁看见哪一部分？
  - 如果不用「没事」把那句话咽回去，你原本想说的是什么？
- **一件小事**：把「我其实希望……」写成一句完整的话。只写给自己看，不用发给任何人。

### 4.3 焦虑 `anxiety`

- **用户可能的说法**：「心里慌」「一直在想明天的事」「睡不着，脑子停不下来」「胡思乱想」「怕搞砸」
- **情绪命名**：焦虑（也可能只是紧张）
- **它通常指向的需求或信号**：它擅长替人预测未来，把还没发生的事当成已经发生。它想做的常常是保护，只是容易做过头。
- **共情确认（示范）**：「慌的时候，人会被『还没发生的事』拽着走。这不是你胆小。」
- **反思问题**：
  - 你在担心的那件事，最坏的结果具体长什么样？它真发生的可能性有多大？
  - 把「我在担心什么」写成一句完整的话之后，它还是一团雾吗？
- **一件小事**：说出 5 样看得见的、4 样摸得到的、3 样听得到的东西，把注意力从预测拉回此刻。

### 4.4 兴奋 `excitement`（正向情绪，同样需要被引导）（本次新增，现有归在 `good`）

- **用户可能的说法**：「太开心了」「我居然做到了」「一下子有好多想法」「停不下来，想马上开始」
- **情绪命名**：兴奋 / 高兴
- **它通常指向的需求或信号**：正向情绪也有信息——它在标记「这件事对我有意义」。值得看清是哪一部分让你兴奋，而不是一笔带过。
- **共情确认（示范）**：「真好，这种时刻值得被记下来——不是因为要正能量，是因为它有用。」
- **反思问题**：
  - 这件事里，最让你兴奋的是哪一小部分？
  - 如果把它再做一次，你最想保留的是哪个条件？
- **一件小事**：把它写进今天的记录里，哪怕只一句。以后低气压的时候，你会需要看到今天这一页。

### 4.5 低落 / 难过 `low`

- **用户可能的说法**：「提不起劲」「想哭」「什么都不想做」「开心不起来」
- **情绪命名**：低落
- **它通常指向的需求或信号**：低落有时是在把决策窗口关小、挡掉几个冲动的选择；也可能只是身体在要休息。它不需要马上被赶走。
- **共情确认（示范）**：「听起来这几天压着不少东西。它不需要马上被赶走，先让它有个地方待着就好。」
- **反思问题**：
  - 如果低落能说话，它想替你推掉哪件事？
  - 今天有没有一小会儿，它是松一点的？
- **一件小事**：说一件今天让你稍微松一点的小事——哪怕只是水喝够了。

### 4.6 疲惫 / 耗竭 `tired`

- **用户可能的说法**：「累」「撑不住了」「睡多久都还是困」「没力气」
- **情绪命名**：疲惫
- **它通常指向的需求或信号**：疲惫常常是账本上的欠额，不是毅力问题。先把最基础的三样补上，比对自己提要求更有用。
- **共情确认（示范）**：「累到这个份上，不是靠意志力能顶过去的。这里缺的不是决心，是账。」
- **反思问题**：
  - 如果把「我应该……」换成一个更小的版本，它会是什么？
  - 最近哪一件事，其实是可以先不还的？
- **一件小事**：给自己排一段 15 分钟什么都不做的时间。不为恢复效率，只是允许停下。

### 4.7 孤独 `lonely`

- **用户可能的说法**：「没人懂」「就我一个人」「找不到人说话」「没人陪」
- **情绪命名**：孤独
- **它通常指向的需求或信号**：孤独常常不是身边没有人，而是「说了也没用」这个预设挡在前面。你已经说出来了，这本身就是一步。
- **共情确认（示范）**：「我在这儿，不会评判你。你已经说出来了，这就是一步。」
- **反思问题**：
  - 你最想被接住的，是这件事本身，还是「有人愿意听」这件事？
  - 如果现在能找一个人，你脑子里第一个出现的是谁？
- **一件小事**：如果想找真人，我可以给你几条 24 小时都有人接的电话；如果只想被听见，继续在这儿说就行。

### 4.8 羞愧 / 自责 `shame`

- **用户可能的说法**：「都怪我」「我怎么又这样」「我是不是太差了」「对不起，是我的问题」
- **情绪命名**：羞愧 / 自责
- **它通常指向的需求或信号**：自责常常是「我很在意这件事」的另一面。它指向的是你心里的标准，不是你的能力——把这两件事分开看会清楚一些。
- **共情确认（示范）**：「听起来你在拿这件事给自己定论。我先不下这个判断。」
- **反思问题**：
  - 如果是朋友做了同一件事，你会怎么对他说？
  - 把「我不好」换成「这件事没成」，那句话还成立吗？
- **一件小事**：把这件事写成「事实」和「我对事实的评价」两栏，先只看事实那一栏。

### 4.9 兜底 `generic`

未命中以上 8 族但用户明确表达「有情绪说不清」时（如「心里堵得慌，说不上来」），用通用模板：只做**命名邀请**（「你说不上来具体是什么——要不要先给它一个临时的名字？」）+ 一段共情 + 一个开放问题，不做信号解读。

## 5. 触发与状态机

### 5.1 自动触发条件（四个条件全部满足）

1. **意图命中**：`MH.guided.detect(text)` 命中 8 族之一（或 `generic`）。
   - 检测在**用户消息**上做，纯本地正则，不依赖模型、不产生网络请求。
   - 与 `local-service.js` 的 `INTENTS` 的关系：`grievance` / `excitement` 需插入 `INTENTS` 数组并**排在 `good` 与 `moodLow` 之前**（现有实现按数组顺序取第一个命中）。
2. **情绪强度 ≥ 0.55**：

   ```
   score = 0.35                                   // 命中即给的基础分
         + 0.20  同一族命中词 ≥ 2 个
         + 0.20  强度副词：非常 / 特别 / 太 / 简直 / 彻底 / 到极点 / 超级 / 超 / 巨 / 贼
         + 0.10  极端表达：受不了 / 崩溃 / 崩了 / 炸了 / 炸裂 / 撑不住 / 撑不下 /
                          忍不住 / 要疯 / 快疯 / 气死 / 气炸 / 烦死 / 累死 / 吓死
         + 0.15  句末「！！」「？？」或「啊啊」类叠字
         + 0.10  累积语义词：凭什么 / 又 / 每次都 / 总是 / 从来 / 一直 / 又是
   score = min(1, score)
   ```
   - `score ≥ 0.55` → 可自动触发
   - `0.35 ≤ score < 0.55` → 不自动触发，但**主动开启时可用**
   - `score < 0.35` → 视为弱信号，不触发
   - **计分口径修订（与架构文档 §4.4 对齐）**：原表算不出 PRD §10.3 自己的用例——「气死了！！」按原表只有 0.50 < 0.55。现将 `气死 / 气炸 / 烦死 / 累死 / 崩了 / 炸裂 / 撑不住 / 撑不下` 归入**极端表达**档，该句 = 0.35 + 0.10 + 0.15 = **0.60** ✓。语义上这些词在汉语里确实属于极端表达，比改阈值或改标点权重更贴合评分语义。
   - **同一个词不得在两档重复计分**：`忍不住` 只在极端表达档计一次，`一直` 只在累积语义档计一次（原表两档都列了，会重复加 0.10）。
   - **硬规则**：禁止把裸单字「烦 / 累 / 慌 / 困」写进识别正则。「有点烦」必须**完全不命中**（用例要求 score < 0.35），一旦裸字进正则就会白拿 0.35 基础分。
   - **`generic` 兜底族不允许自动触发**（`auto = false`）：自动模式命中 generic → 静默（reason `NO_EMOTION`），只有手动开启才用它。理由：读不出情绪时还自动出卡，等于强行解读，与「不替用户定性」相悖。
3. **对话轮次门槛**：本次会话（自上次「清空对话」起）用户发言 ≥ 2 轮。第一句话不引导。
4. **频率未超限**（见 5.2）且 `prefs.guidedAuto === true` 且未命中危机词。

### 5.2 频率限制（建议值）

| 限制项 | 数值 | 说明 |
| --- | --- | --- |
| 每日自动引导上限 | **2 次** | 按自然日计数，跨日重置 |
| 同一情绪族 | **24 小时内 1 次** | 避免同一天反复被讲同一个道理 |
| 两次引导之间的最小轮次 | **用户再发言 3 轮** | 用户连续说 3 句后才可能再触发 |
| 两次引导之间的最小间隔 | **30 分钟** | 防止短时间内刷屏 |
| 被拒后冷静期 | **7 天** | 「这次先不了」后 7 天内不自动触发；手动开启不受限 |
| 单会话内步数 | **1 张卡**（P1 可 +1 轮） | 不连环追问 |
| 本地存储不可用 | 每日上限降为 **1 次** | 状态只活在内存，保守处理 |

### 5.3 主动开启入口

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 设置页开关 | 「数据与外观」区新增一行 `setting-row`，标题「情绪引导」，描述见文案表；默认 **开** | 关闭 → 永不自动触发；手动按钮保留 |
| 对话页按钮 | `chat__composer` 内，发送按钮左侧，`id: cmpGuide`，文案「引导我看看」 | 立即出一张卡，绕过频率与冷静期；无情绪命中时用 `generic` 模板 |
| 指令 | 输入框输入 `/引导`（也接受 `/guided`）后发送 | 等价于点击按钮，发言本身不入正常回复流程 |

### 5.4 状态机

```
                    ┌──────────────────────────────┐
                    │        IDLE（默认待命）        │
                    └───────────────┬──────────────┘
                                    │ 用户发一条消息
                                    ▼
                          detect() → 命中情绪族？
                          否 ──► 回 IDLE（静默，不提示）
                          是
                                    ▼
                          危机词？── 是 ──► CRISIS（求助资源，终止）
                                    │ 否
                                    ▼
                    强度 ≥0.55 且 轮次≥2 且 频率未超限 且 guidedAuto？
                          否 ──► 回 IDLE（静默）
                          是
                                    ▼
                            OFFERED（出引导卡）
                          /         |          \
                  「我记下了」   「这次先不了」   「不再自动引导」
                    /               |                \
              ENGAGED           DECLINED           DISABLED
           （记 history，      （declineAt=now，   （prefs.guidedAuto=false，
             P1 可续一轮）      7 天冷静期）        需到设置页才能再开）
                    \               |                \
                     └──────────► 回 IDLE ◄───────────┘
```

**「用户拒绝继续」的降级处理（重点）**

1. 点「这次先不了」→ 卡片当场收起为一行系统提示：`已跳过这一次的引导。七天内我不会再主动提起，你想聊的时候，「引导我看看」一直都在。`
2. `MH.store.guided.decline()` 写入 `declineAt`，7 天内 `shouldTrigger()` 返回 false（含所有情绪族，不只是刚被拒的那一族）。
3. 冷静期内**不降低主动入口的可见性**，也不在回复里暗示「你上次没看」。
4. 冷静期结束后恢复自动触发，且本次不再重提上次被拒的事。
4b. **冷静期是「承诺」，只能靠时间走完，不被任何互动提前清除**（与架构文档 v2 对齐）：
    - 冷静期内手动点「引导我看看」**照常出卡**（绕过），但**不清除 `declineAt`**——第 4 天手动开一次，第 5 天仍然不会自动出卡。
    - 理由：拒绝时那句 toast 已经向用户说出口「七天内我不会再主动提起」。这是**说出去的承诺**，不能因为用户自己点了一次就悄悄收回——否则承诺变成"看情况"。
    - 唯一例外：用户到设置页重新打开自动引导（`guidedAuto` 由 false 改 true）时清空 `declineAt` 与 `declineCount`，因为那是显式改变设置，不是"再试一次"。
    - 对比：`declineCount`（阈值档位）**可以**被「我记下了」归零——它是学习信号，不是承诺。
    - **实现边界（与架构文档 v3 §4.8 对齐，防止被"顺手优化"写反）**：
      - `MH.guided.enableAuto()` 是**唯一**会写 `declineAt = 0` 的业务函数，只有 `settings.js` 开关 false→true 时调用；
      - `tryManual()` / `record()` / `buildMessage()` 任何路径都不得写 `declineAt = 0`；
      - 冷静期判定统一走纯函数 `MH.guided.inCooldown(now, state)`，视图里禁止另写 `now - declineAt < 7 天`（同一规则两份实现必漏改）。
4c. **冷静期内不新增任何提示、轻提示或出口文案**（含 §8.8 的同族轻提示）。「引导我看看」按钮常驻可见**就是**那个出口，不再额外用一句话去说明它。
    理由：出口信息在**用户点拒绝的那一刻**已经给过一次（toast 原文即含「你想聊的时候，「引导我看看」一直都在」），时机最准；之后再补一句，语义上就变成「我注意到你上次没看」，正是第 3 条要避免的东西。冷静期结束日也不给「我又可以提醒你了」这类提示。
5. 连续被拒 2 次后（`declineCount >= 2`），自动触发阈值由 0.55 上调到 0.7（只对一个更强的信号出手）。
   **复位规则（原 PRD 未定义，与架构文档 §10-Q6 对齐）**：本次只做「升」不做「自动降」——
   用户点「我记下了」（`outcome: 'acted'`）时 `declineCount` 归零。
   不用「符合」反馈做复位：用户可能认可这一版读法，但仍不想被反复引导；**只有主动参与一次才说明他愿意继续**。

## 6. 内容结构定义

### 6.1 数据结构

```js
{
  schema: 'moodhub.guided/v1',
  emotion: { key: 'anger', name: '愤怒', alt: ['生气', '窝火', '火大'] },

  // ① 情绪命名：给它一个名字，并把这个命名权明确交回给用户
  name:     '听起来，这更像是一股愤怒。你觉得准吗？叫它别的也行。',

  // ② 共情确认：先确认它合理，不评价好坏
  validate: '不是你脾气差，是有什么东西顶到你了。',

  // ③ 信号解读：一种可能的读法，不是结论
  signal:   '愤怒常常是在说有一条边界被越过了。这一次，被越过的可能是「被提前告知」那条线。',

  // ④ 反思问题：留给本人，不代替本人回答
  questions: [
    '如果把它翻译成一句「我需要……」，会是哪一个词？',
    '这件事里，真正被碰到的那条线是什么？'
  ],

  // ⑤ 小行动：小到今天就能做，且不做也没关系
  action:   '先给身体一个出口：把想说的话写下来，先不发。等心率降下来再决定要不要表达。',

  // ⑥ 温和收尾：声明这是一版读法 + 请求校正
  closing:  '这些只是基于你这句话的一版读法，不是给你的定性。哪一句不准，你说一句，我就改写它。'
}
```

### 6.2 与 XAI 三档的映射

`MH.guided.build()` 把上面 6 段折叠成一份 xai 规格，再交给 `MH.xai.compose`：

| 档位 | 内容 |
| --- | --- |
| **短** | ① 命名 + ② 共情（各一句） |
| **中** | ① + ② + ③ 信号 + ⑤ 小行动 |
| **长** | ① + ② + ③ + ④ 反思问题（列全）+ ⑤ + 推理边界（「我只读到你这一句话和最近 14 天的聚合值，看不到昨天那件具体的事」）+ ⑥ |

三档与依据、请求校正、反馈按钮全部复用 `companion.js` 现有的 `xaiBody(msg)`，**不新造一套解释 UI**。

**渲染口径（原 PRD §6.2 与 §7.1 冲突，与架构文档 §3.4 / §10-Q5 对齐）**

引导卡里 `xaiBody` 的 `.xai__body` 文本区**不渲染**（`opts.body = false`），因为三档文本与下面三个同名结构化区块内容重复。改为：**三档控制三个结构化区块的展开范围**，① 命名 + ② 共情**常显**（不折叠整张卡）。

| 档位 | ③ 信号 | ④ 反思问题 | ⑤ 小行动 | 推理边界 |
| --- | --- | --- | --- | --- |
| 短 | 收起 | 收起 | 收起 | — |
| 中（默认） | 展开 | 收起 | 展开 | — |
| 长 | 展开 | 展开 | 展开 | 显示 |

- 这张表是本 PRD §6.2 那一行的忠实实现：中档 = ①+②+③+⑤（不含 ④），长档才把 ④ 摊开并补推理边界。**按架构原方案执行，不再把中档也展开反思问题**——递进感是 MoodHub 解释层的核心（短=一句话，长=把推论摊开），折叠的区块仍保留可见标题「可以问自己」，一点即开。
- 空的区块（signal 为空 / questions 为空 / action 为空）**不渲染节点**，而不是渲染空标题。
- 用户手动点过某个区块标题后，该区块**脱离档位联动**，不再被切档改变。
- 移动端（≤620px）`questions` / `action` 初始为收起，不受档位影响。
- 三档文本仍完整存在于 `layers` 里，供导出与测试断言；**无障碍朗读以区块实际渲染内容为准**，不要再补一份 `sr-only` 的 layers 文本，否则屏幕阅读器会把同一段读两遍。
- **待补**：长档的推理边界句（`boundary()`）目前只存在于 `layers.long`，而文本区不渲染 → 界面上看不到。建议在长档时把它渲染出来（可并入自动展开的 `.xai__basis`，或作为独立小段放在行动区块之后、收尾句之前），否则「长＝把推论摊开，包括推理缺口」这条 xai 承诺在引导卡上落空。

### 6.3 可配置模板

```js
MH.guided.TEMPLATES = {
  anger: {
    name:     ['听起来，这更像是一股{{name}}。你觉得准吗？叫它别的也行。'],
    validate: ['不是你脾气差，是有什么东西顶到你了。',
               '它会升上来，说明这件事对你不是无所谓。'],
    signal:   ['{{name}}常常是在说有一条边界被越过了。这一次，被越过的可能是「{{need}}」那条线。'],
    questions:['如果把它翻译成一句「我需要……」，会是哪一个词？',
               '这件事里，真正被碰到的那条线是什么？'],
    actions:  ['先给身体一个出口：把想说的话写下来，先不发。等心率降下来再决定要不要表达。']
  },
  /* grievance / anxiety / excitement / low / tired / lonely / shame / generic 同构 */
  generic: { /* 只有 name + validate + questions，signal 留空 */ }
};

MH.guided.EMOTIONS = [
  { key: 'grievance', name: '委屈', alt: ['被忽略', '不甘'], need: '被看见',
    re: /委屈|凭什么|背锅|明明.*努力|没人看见|我说了不算|我不重要/ },
  /* … */
];
```

**占位符**：`{{name}}` 情绪名 / `{{alt}}` 同族别名（首个）/ `{{need}}` 该族指向的需要 / `{{quote}}` 用户原话的 ≤12 字片段 / `{{action}}` 小行动。

**`{{quote}}` 的口径修订（与架构文档 §10-Q3 对齐）**：原 PRD 写的「仅在卡内展示，不落库」不成立——引导消息本身要 `chat.append` 进 localStorage，写进去就是落库。**P0 一律不使用 `{{quote}}`**：`fill()` 把它替换为空串，9 组模板都不引用它，`payload.guided` 不含 `quote` 字段。理由：用户那句话本来就在他自己的气泡里，再复制一份进存储既无收益，也与「只存必要内容」的隐私承诺相悖。占位符保留给 P1 的云端个性化（P1 上云端时同样受 `allowExternal()` 约束）。

**`{{alt}}` 同理**：P0 不使用，保留给 P1「换个说法」。

**有意保留的一处例外**：`evidence` 里仍会存命中的情绪词（如「这一句话里读到的线索：气死、凭什么」，上限 4 个）。这不是复述，是**可核查的依据**——用户要能知道「你凭什么说我是委屈」，才能点「不符合」纠正它。这与 MoodHub 的 `我依据的是这些` 是同一条承诺，不要为了和 `{{quote}}` 一致把它一起删掉。

**扩展一类情绪 = 两步**：
1. 在 `EMOTIONS` 加一条 `{key, name, alt, need, re}`；
2. 在 `TEMPLATES` 加同名键（可只写 `name` 与 `validate`，其余回落到 `generic`）。

模板缺键一律回落到 `generic`，**不允许出现空段或 `undefined` 出现在界面上**。`MH.guided.build()` 对每段做 `String(x || '')` 兜底，并在 `signal`/`questions` 为空时自动跳过对应 UI 区块。

**云端提示词模板（P1）**：`MH.guided.prompt(emotionKey, quote)` 输出一段给模型的系统提示，内含同样的 6 段结构与语气约束（不定性、不劝说、结尾请求校正），模型返回文本经 `MH.xai.explainProse` 拆三档；失败或返回为空则回落到本地模板。

### 7.3 层次与可折叠性

| 区块 | 类名 | 默认状态 |
| --- | --- | --- |
| 卡头：徽标「情绪引导」+ 情绪名 chip + 关闭「✕」 | `.gl__head` | 常显（「换个说法」属 P1，本次不渲染也不留占位） |
| 命名 + 共情 | `.gl__name` / `.gl__validate` | **常显** |
| 三档切换 | 复用 `.xai__switch` | 常显，跟随 `prefs.xaiLevel`（默认「中」） |
| 信号解读 | `.gl__block[data-block=signal]` | 随档位（见 §6.2 表） |
| 反思问题 | `.gl__block[data-block=questions]` | 随档位；≤620px 恒收起 |
| 小行动 + 按钮组 | `.gl__block[data-block=action]` | 随档位；≤620px 恒收起 |
| 收尾 + 依据 + 反馈 | 复用 `.xai__ask` / `.xai__basis` / `.xai__fb` | 常显 |
| 页脚：不再自动引导 | `.gl__foot` | 常显，弱化为文字链，不用危险色 |

- 卡片本身：**不整体默认折叠**（折叠了就等于没引导），被折叠的只是「信号 / 问题 / 行动」三个区块，且各自保留**可见标题**（如「可以问自己」），一点即开。
- 「我记下了」按钮点击后 → `outcome: 'acted'`，按钮 `disabled` 并追加 `.hint`「已记下」，**卡片本身保持可读不消失**。
- 卡片用 `var(--surface-2)` 底 + 1px `var(--line)` 边 + 左侧 3px 情绪色条（沿用现有 CSS 变量，不引入新色板）。
- 卡片用 `var(--surface-2)` 底 + 1px `var(--line)` 边 + 左侧 3px 情绪色条（沿用现有 CSS 变量，不引入新色板）。

### 7.4 无障碍要点

- 卡片 `role="group"` + `aria-label="情绪引导 · 愤怒"`，出现时 `aria-live="polite"`（不打断屏幕阅读器当前朗读）。
- 「这次先不了」为 `<button>`，带 `aria-label="跳过这一次引导"`，不用纯图标 ✕。
- 所有状态按钮用 `aria-pressed`（复用 `xai__btn` 的既有做法）。
- 键盘顺序：命名 → 三档 → 信号 → 问题 → 行动按钮 → 反馈 → 页脚，与视觉顺序一致。
- 焦点：卡片插入后**不抢焦点**（不像正常回复那样 `input.focus()` 之外再移动焦点），避免打断正在打字的人。
- 移动端触控目标 ≥ 40px 高；按钮竖排全宽。

## 8. 边界与异常处理

| # | 场景 | 产品层面的处理方式 |
| --- | --- | --- |
| 1 | **情绪话题缺失**（问候 / 纯提问 / 事实陈述，落到 `fallback` 或 `greeting` 意图） | 不触发，且**不追问**「你是不是有情绪」。手动点「引导我看看」时用 `generic` 模板，出「还没读到明显的情绪信号。要不要先给它一个临时的名字？」 |
| 2 | **对话轮次不足**（会话内用户发言 < 2 轮） | 不自动触发。手动开启时降级为「只做命名」：只出 ① 命名 + ② 共情两段，跳过信号解读与行动，并附一句「信息还不多，这一步我只做命名，不做解读。」 |
| 3 | **用户拒绝继续**（点「这次先不了」/ 直接无视继续说话） | 点按钮 → 卡片收起为一行系统提示 + 7 天冷静期（见 §5.4）。无视（继续发消息）**不视为拒绝**，只按正常回复处理，不追加引导、不追问。冷静期内手动开启照常出卡但**不清除冷静期**（§5.4-4b），且不出任何形式的轻提示（§5.4-4c）。 |
| 4 | **危机词命中** | 引导完全不触发（自动与手动都不），只出求助资源与热线；`state` 不写入 `history`（`reason: 'CRISIS'`，与 `.me` 的既有做法一致）。 |
| 5 | **本地存储不可用**（隐私模式 / 空间满） | 频率状态降级为内存对象，功能不中断；`MH.store.storageAvailable === false` 时每日自动上限降为 1 次；写入失败沿用 store 已有的「本机存储写入失败」toast，不额外弹错。 |
| 6 | **模型降级或出错** | 引导正文**始终由本地模板生成**，不依赖云端结果；云端回复失败时先保证正常回复，引导卡照常出（若 `MH.models.run` 走 `catch` 分支即完全失败，则**不出**引导卡，避免两条错误叠在一起）。P1 云端增强失败时静默回落到本地模板。 |
| 7 | **情绪强度过低**（只出现「有点」「还行」，score < 0.35） | 不触发。不把中性表达当成情绪信号，不在回复里暗示「你其实有情绪」。 |
| 8 | **同一情绪重复出现**（24h 内同族已引导过） | 不重复出同类卡；追加一句**最轻的系统提示**：`role: 'sys'` 气泡（现有 `.bubble--sys` 样式，不带时间戳），文本为固定句「昨天我们聊到过它。如果你想再往里走一层，可以点『引导我看看』。」**30 分钟节流**（模块级 `lastHintAt`，每次会话最多一次），避免它变成新的打扰源。冷静期（7 天）内**不出**这条提示——它会变成「你上次没看」的暗示。手动开启不受此限。 |
| 9 | **一次同时命中多族** | 取 score 最高者；并列时取 `EMOTIONS` 数组靠前的一族，并在命名里带上相邻族，如「愤怒（可能夹着委屈）」，把判断权交回用户。 |
| 10 | **模板缺失 / 字段为空** | `build()` 兜底到 `generic` 并对每段 `String(x||'')`；`signal` 或 `questions` 为空时跳过对应 UI 区块，绝不出现空标题或 `undefined`。 |
| 11 | **`prefs.guidedAuto` 为 false 时手动开启** | 允许。关闭的只是「自动」，不是功能本身。 |
| 12 | **对话被清空** | `turnsSince` 归零，轮次门槛重新计数；`dayAuto` / 冷静期等跨会话限制**保持不变**（防止靠清空绕过频率限制）。 |

## 9. 待确认问题

1. **引导卡的呈现形式**：作为**独立一条 AI 消息**追加在正常回复之后（推荐，可单独被标记「不符合」、可单独退出），还是并进同一条回复的末尾？——影响 `chat.append` 的调用方式与历史导出结构。
2. **自动触发默认开还是关**：推荐默认「开」，并在用户第一次进入陪伴页时用一条系统提示说明一次「这里会在你情绪明显时多给一次引导，随时可关」。若团队认为默认关更符合「不打扰」，需拍板。
3. **云端模型启用时，引导正文是否也交给云端**：推荐默认**只用本地模板**，云端仅当「已授权外发」且设置里额外勾选「引导也用云端」时才启用（P1）。是否需要本次就做这个开关？
4. **频率数值是否需要更保守**：每日 2 次 / 同族 24h 1 次 / 被拒冷静期 7 天 / 间隔 3 轮——这是按「一个月可能聊 20 次」的节奏估的。若实际使用频率更高（每天多次），建议把每日上限降到 1 次。
5. **引导是否要写回「记录」**：P2 的「一键写入当天备注」是否值得本次就做？写入意味着情绪内容从对话进入记录区，需要在记录页也能看到来源说明。

### 10.2 关键实现要点

- **DOM 无关**：`guided.js` 只做识别、评分、状态判定与内容生成，与 `xai.js` 同等约束，便于后续抽给小程序 / 桌面端。
- **不新造解释 UI**：引导卡内部直接 `appendChild(xaiBody(msg))`，三档 / 依据 / 反馈全部复用，保证「可纠正」这一条承诺在引导内容上同样成立。
- **不新增网络出口**：`detect` 与 `build` 全本地；`MH.guided.prompt()`（P1）只在 `allowExternal()` 为真且有显式开关时才被调用。
- **频率判定集中在一个函数**：`MH.guided.shouldTrigger({ text, turns, now })` 返回 `{ok, reason}`，`reason` 便于测试断言（如 `CRISIS` / `COOLDOWN` / `DAILY_LIMIT` / `SAME_EMOTION` / `TURNS` / `INTENSITY` / `DISABLED`）。
- **引导消息的落库结构**：
  ```js
  MH.store.chat.append({
    role: 'ai', text, tags: ['引导式学习', emotion.name],
    layers, payload: { guided: { schema, emotion, signal, questions, action }, model: {...} }
  });
  ```
  `bubble()` 通过 `msg.payload && msg.payload.guided` 判断走 `guidedCard` 还是普通 `xaiBody`。

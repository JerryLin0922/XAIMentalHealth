# MoodHub Web

基于浏览器的跨平台心情记录与管理应用，定位为 **powered by health data** 的情感陪伴空间。在一个界面里同时追踪 **心情 / 睡眠 / 心率 / 压力** 四项指标。

> **它不是诊断工具。** MoodHub Web 不构成医疗诊断、治疗或处方建议，仅供自我觉察与温和引导。若你正处于心理危机中，请优先联系专业资源：全国统一心理援助热线 **12356**（24 小时），或紧急电话 **110 / 120**。

## 隐私边界（写在最前面）

| 项目    | 行为                                                                                       |
| ----- | ---------------------------------------------------------------------------------------- |
| 数据存储  | 只写入本设备浏览器的 `localStorage`（会话态写入 `sessionStorage`），**不上传、不同步、无账号、无遥测**                    |
| 网络请求  | **默认零**。全站无外部资源引用，断网可用。只有在「模型」页显式开启外发授权并选择云端模型后，才会产生指向所选服务商的直连请求                         |
| 对话数据  | 发起对话时只把**最近 14 天的统计摘要**（四项指标的均值、极值、最近值、每周趋势斜率）交给本地服务，**不含任何单条记录、日期明细或备注原文**              |
| 上传文件  | `FileReader` 本地读取，从不上传；默认**仅本次会话**（内存态，刷新即消失），只有显式勾选「保存到本机」才写入 localStorage，且有 600k 字符预算 |
| 第三方数据 | 「导入」页的文件同样只进内存：解析、清洗、去重全在本机完成，**原始表格一行都不落盘**；只有转换后的四项指标（与可选的备注）会写进记录                     |
| 问答上下文 | 内置「健康记录」来源只以 14 天聚合摘要参与上下文；用户自己上传的文件按勾选范围参与                                              |
| 云端模型  | 默认关闭。开启后由浏览器直连服务商，不经过任何中间服务器；密钥默认仅本次会话，勾选保存才落盘且需重新验证密码；备份导出不含密钥；危机信号强制本地                 |
| 本地服务  | 跑在页面进程内的规则引擎（`local://moodhub/companion`），不是云端接口                                         |
| 口令    | 用 PBKDF2-SHA256 + 随机盐派生校验，口令本身与明文都不落盘；它锁的是这台设备上的访问入口                                     |
| 信任设备  | 勾选后本机只保存一枚**随机令牌与到期时间**，到期自动要求重新输入密码                                                     |

界面上「看板」底部、「设置 → 数据」与「陪伴」页都有本地存储边界的显式提示。

## 运行

零依赖、零构建。任选一种方式：

```bash
# 方式一：本地静态服务（推荐，localStorage 行为与线上一致）
cd moodhub-web
node serve.cjs                  # http://localhost:5173
# 或：python -m http.server 5173

# 方式二：直接双击 index.html
# 说明：部分浏览器（如 Safari）会限制 file:// 下的 localStorage，此时记录无法保存
```

回归测试（不需要浏览器）：

```bash
node tests/run-all.cjs     # 一次跑完下面四个套件（推荐；CI 也用它，失败退出码非 0）

node tests/smoke.cjs       # 核心层 131 项：口令派生、表单校验、统计聚合、检索、问答、模型路由与降级、第三方导入（ZIP/XLSX 解析、来源识别、清洗去重、冲突策略）
node tests/dom-models.cjs  # 视图层 54 项：用极简 DOM 桩跑真实的模型页，验证分区切换、筛选排序、详情、新增 / 编辑 / 删除 / 启停 / 密钥残留
node tests/dom-import.cjs  # 视图层 31 项：跑真实的导入页，验证选文件 → 解析 → 改映射 → 导入 → 撤销 → 跳记录整条链路
node tests/import-analytics.cjs  # 导入 + 分析单测 75 项：虚拟模板数据导入（正常 / 空 / 格式错误 / 缺失字段）、统计聚合（均值 / 极值 / 趋势 / 分类）、边界（6 万行超大 / 重复 / 并发 / 撤销）、分析稳定性与异常分支
```

静态部署：把整个 `moodhub-web/` 目录丢到任意静态托管（GitHub Pages / Nginx / OSS）即可，无需构建步骤。

### 启用加密云端同步（可选）

```bash
# 1) 部署后端（Cloudflare Worker + D1）
cd worker && npm install
wrangler d1 create moodhub && wrangler secret put SESSION_SECRET
npm run db:init && npm run deploy     # 记下 https://<subdomain>.workers.dev

# 2) 前端指向后端

#    小程序：miniprogram/app.js 的 globalData.apiBase。
# 3) 在应用「设置 → 云端同步」输入云端密码完成注册/登录，即可端到端加密同步。
```
全部加密逻辑见 [docs/architecture.md](docs/architecture.md)；后端说明见 [worker/README.md](worker/README.md)，小程序见 [miniprogram/README.md](miniprogram/README.md)。

## 新增能力（端到端加密同步 · 动态网站 · 微信小程序）

> 在「本地优先、零上传」的原有承诺之上，新增**可选的**端到端加密云端同步，以及对应的
> 动态网站后端与微信小程序端。核心是一份三端共享的纯 JS 加密内核（`shared/cipher.js`），
> 服务端永远只保存密文、读不到任何明文。设计细节见 [docs/architecture.md](docs/architecture.md)。

1. **用户数据加密存储**：AES-256-CTR + HMAC-SHA256（Encrypt-then-MAC），口令派生密钥。
   支持 `local`（本机直加密）与 `cloud`（信封加密：随机 dataKey 加密数据、再用口令密钥包裹后上传）
   两种模式；密钥仅在内存中派生，刷新即丢。验证见 `tests/cipher.cjs`。
2. **网站动态化**：新增 `worker/`（Cloudflare Worker + D1）提供 `/api/auth/*` 与 `/api/vault`，
   负责登录态（HMAC 签名 Cookie）、动态渲染的 `/account` 页，以及只存密文的加密数据托管。
   前端通过 `js/core/vault.js` + `js/views/cloud.js` 接入，**默认仍是纯本地**，云端为显式开关。
3. **微信小程序**：`miniprogram/` 复用同一份加密内核，实现与网站对齐的认证、加密存储/读取、
   看板与记录管理、以及加密云同步（详见 [miniprogram/README.md](miniprogram/README.md)）。

## 功能

### 1. 登录页

- 首次打开创建本机账户（用户名 2–24 字，密码 ≥ 6 位），之后输入密码解锁
- **保存密码并信任此设备**：可选 1 / 7 / 30 天。勾选后写入随机令牌与到期时间，到期自动回到登录页；不勾选则只在当前标签页会话内有效
- **定期重新验证**：信任到期、空闲超时（默认 15 分钟，可设 5/15/30 分钟或关闭）、手动锁定，以及导出 / 清空 / 撤销信任等敏感操作前，都会要求重新输入密码
- 忘记密码没有找回通道（没有服务器），只能清空本机数据重来——这一点在界面上如实说明

### 2. 数据看板

- 四项指标各一张卡：**均值 + 每周变化量 + 最低 / 最高 / 最近值 + 迷你趋势线**
- 四项指标各一张独立折线图，颜色、量程、单位彼此区分（心情 1–5 分 / 睡眠 0–16 h / 心率 30–200 bpm / 压力 0–10 分）
- 区间可切 7 / 14 / 30 天；空白天在图上断开而不是补零
- 最近 5 条记录可直接跳到编辑

### 3. 列表管理

- 筛选：日期区间、心情 ≥/≤、压力 ≥/≤、睡眠下限、心率上限、备注关键词
- 排序：日期 / 心情 / 睡眠 / 心率 / 压力，点表头即可升降切换
- 空态区分「还没有记录」和「没有符合条件的记录」

### 4. 表单编辑

- 新增与修改共用一个弹窗：日期、时间（选填）、四项指标（滑块 + 数字输入双向同步）、备注（≤ 500 字）
- 校验覆盖：日期必填且不晚于今天、四项指标必填且在各自量程内、整数 / 0.5 步长约束、备注长度
- 错误提示落在字段下方，输入框标红；保存后 toast 反馈并刷新当前页
- 修改态显示创建 / 最后修改时间，可直接删除

### 5. 智能问答（本地检索增强）

- **多类型输入**：拖入或选择 CSV / TSV / JSON / 文本（md、log、txt）文件，也可以直接粘贴一段内容当作来源；内置「本机健康记录」作为一个可选来源参与
- **解析**：CSV 自动识别逗号 / 制表符 / 分号分隔与引号包裹，识别日期列与指标列（心情 / 睡眠 / 心率 / 压力 / 步数 / HRV / 血氧 / 运动）；表格型来源还可以一键「转为记录」写进本机记录
- **上下文整合**：来源切成 ~600 字的块 → BM25（中文按字 + 二元组、英文按词）检索出 Top-K 证据，同一来源最多取 2 块以保证多来源均衡 → 在字符预算（6k / 12k / 24k 可调）内与「补充说明」拼装成上下文
- **响应生成**：除了引用原文，还会对表格列做真实的数值计算（平均 / 最高 / 最低 / 最近 / 趋势 / 条数），答案里明确写出列名与样本数；证据带来源名与相关度，可展开查看本次实际组装的上下文
- **持久化**：来源默认「仅本次会话」（只在内存里，刷新即消失），勾选「保存到本机」才写入 localStorage，并有 600k 字符总预算保护；命中危机词时不做分析，直接转求助通道

### 6. 陪伴（树洞）

- 发送消息时构造 `moodhub.summary/v1` 摘要交给本地服务，页面上有「查看本次发送给本地服务的内容」折叠面板，可逐字检查传出的是什么
- 服务入口会严格裁剪入参：任何额外字段（含原始记录）都会被丢弃
- 命中危机词时立即返回求助资源卡，不做任何"分析"
- 对话历史同样只存本机，可一键清空

### 7. 第三方健康与运动数据接入

一个五步向导：**选择来源 → 字段映射 → 清洗与去重 → 导入进度 → 结果反馈**。所有解析都在浏览器里完成。

- **终端厂商**：华为运动健康、Apple 健康（iOS/watchOS）、Google Fit、Android Health Connect、OPPO / 欢律、vivo 健康、小米穿戴 / Zepp Life、Garmin 与其它运动手表；每张画像都写了「去哪儿导出」的说明
- **通用格式**：CSV / TSV（自动识别逗号、制表符、分号）、Excel（xlsx / xlsm）、JSON（含 Health Auto Export 结构）、Apple 健康 export.xml，以及 ZIP 容器（Health Connect、Garmin Connect 的整包导出可以直接拖进来）
- **字段映射**：先用专属列名、再用通用别名、最后看取值形态，三层打分自动选列；认出来的高风险换算（睡眠分钟 / 秒、压力百分制、血氧 0–1）会在界面上写清楚处理规则，也支持手动改列与改单位
- **清洗**：日期解析失败、落在未来、超出量程、整行没有指标的行都会单独记录；可按策略丢弃或截断到量程边界；可只导入指定日期区间
- **时间对齐**：时间戳按本机时区落到日历日；跨夜睡眠默认归属「起床日」；Apple 健康与含起止区间的表按同一口径汇总
- **去重**：批内按「日期 + 时刻」先到先得合并（所以睡眠表 + 心率表可以分两个文件导），再与本机记录按四种策略比对 —— 补齐（默认，只填空缺）/ 覆盖 / 跳过 / 追加
- **进度与反馈**：实时进度百分比、当前阶段与已处理行数，随时可取消（取消后本机数据不变）；结束时给出新增 / 更新 / 跳过 / 无效行统计，逐条列出被跳过的内容，并支持一键撤销本次导入
- **辅助指标**：步数 / HRV / 血氧 / 运动时长 / 正念时长可写进备注（如「自动导入：步数 8213 步 · HRV 42 ms」），不占用四项指标
- **错误处理**：`UNSUPPORTED_FORMAT / FILE_TOO_LARGE / PARSE_FAILED / EMPTY_DATA / NO_DATE_COLUMN / NO_METRIC_COLUMN / NO_VALID_ROWS / CANCELLED / COMMIT_FAILED` 等错误码都带一句该怎么办的说明，单个文件失败不影响其它文件

设计说明见 [docs/health-import-spec.md](docs/health-import-spec.md)：加一个数据源只需在 `vendors.js` 的 `PROFILES` 里加一条画像。

### 8. 模型管理

页面分四个分区（分段导航，完整设计见 [docs/models-page-spec.md](docs/models-page-spec.md)）：

| 分区       | 作用                                                                  |
| -------- | ------------------------------------------------------------------- |
| **模型库**  | 发现与比较：本地引擎 + 全部连接以卡片/表格呈现，支持搜索、按类型/能力/状态筛选、按推荐/名称/窗口/成本排序、分页；点开可看详情 |
| **场景配置** | 选择：陪伴与问答各自独立选模型，附推荐与可读理由，一键采用                                       |
| **连接管理** | 配置：服务商预填、密钥仅会话或落盘、测试连接、启停、编辑、删除                                     |
| **调用日志** | 观测：按场景/结果筛选，实测统计（次数、成功、降级、P50、P95 延迟）                               |

**模型详情**包含：基本信息、版本与候选版本、场景参数说明、能力、性能（厂商档位标注「估算」+ 本机日志派生「实测」）、适用场景、使用说明，云端模型额外给出**密钥已掩码**的外发预览。

- **本地内置模型（默认）**：`本地规则引擎`（陪伴）与 `本地检索 · 统计引擎`（问答），离线可用、零配置、数据完全不出设备
- **云端接入（可选）**：DeepSeek / 通义千问 / 腾讯混元 / Gemini / OpenAI / Anthropic / 自定义 OpenAI 兼容端点。请求由浏览器**直连服务商**，不经过任何中间服务器；默认关闭，需显式开启外发授权
- **可扩展架构**：加服务商 = 在 `registry.js` 的 `PRESETS` 加一条；加协议 = 在 `adapters.js` 实现同签名函数 `{ conn, req } → { text }` 并注册。现有协议：`local` / `openai-compatible` / `gemini` / `anthropic`
- **场景切换**：陪伴与问答各自独立选模型，互不干扰；删除连接会自动回落到该场景的本地默认模型
- **场景推荐**：问答按上下文字符数挑"窗口够用且最经济"的模型；陪伴挑 flash / turbo / mini / haiku 一类快速便宜模型；无可用连接或未授权外发时一律推荐本地，并给出可读的理由
- **统一接口与错误**：`MH.models.run(scenario, payload)` 单一入口，返回统一结构（文本、模型、隐私级别、是否降级、错误码、耗时、外发预览）。错误统一映射为 `NO_KEY / MISSING_CONFIG / AUTH / RATE_LIMIT / SERVER / TIMEOUT / NETWORK / EMPTY / BAD_JSON / NOT_FOUND / CRISIS_GUARD / BLOCKED_BY_PRIVACY`，带 `retryable` 标记
- **自动降级**：云端调用失败→自动改用本地引擎并在界面上说明原因，功能不中断；外发预览会掩码密钥；调用日志（场景/模型/耗时/失败原因）只存本机

两条硬约束：检测到危机信号时**强制本地、绝不外发**；未开启外发授权时云端模型不会被真正调用。

### 9. 设置

- 账户：修改密码（需验证旧密码）、口令派生方式与时间展示
- 安全：信任设备 / 续期 / 撤销、信任剩余时长、空闲锁定、立即锁定
- 数据：记录与对话条数、localStorage 占用、导出 JSON 备份、导入（合并 / 替换）、第三方健康数据导入入口、清空全部（原则上涉及隐私的操作都需重新验证密码）
- 外观：浅色 / 深色 / 跟随系统

## 已知边界

- 数据不跨设备：换设备、换浏览器、清理站点数据或使用隐私模式都会丢失记录，请定期在「设置」里导出 JSON
- 口令是本机访问锁，不等同于磁盘加密；有更高保密需求请配合操作系统级加密
- 无 `crypto.subtle` 的环境（少数老浏览器 / 非安全上下文）会回退到内置纯 JS PBKDF2，迭代次数自动降到 10k，界面不做额外提示
- 第三方导入的支持面：单个文件 ≤ 24 MB、单张表 ≤ 6 万行；Excel 仅支持 `.xlsx / .xlsm`（旧版 `.xls` 请另存为 CSV）；Garmin / Suunto 等设备的 `.fit` 二进制暂不支持，请从厂商后台导出 CSV；Apple 健康导出的是 `export.zip / export.xml`，ZIP 可以直接拖进来，超大导出（数百 MB）需要先缩短时间范围
- 导入时有属性不认识也不用慌：辅助指标只会写进备注（步数 / HRV / 血氧 / 运动时长 / 正念时长），不会占用四项指标；这个来源没有的属性一律留空，不会替你编数字
